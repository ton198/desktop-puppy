# Desktop Puppy 需求与设计说明

**日期：** 2026-09-22
**状态：** 架构决策已确认，等待按实施计划创建产品代码
**项目性质：** 个人使用、非商业桌面宠物应用

## 1. 产品定位

Desktop Puppy 是一个运行在 Windows 桌面的调皮型常驻桌宠。它通过轻量动画、点击和受击互动、低频随机活动、每日问候、AI 台词和每日幽默总结，为个人用户提供有个性的桌面陪伴。

产品不以生产力工具为主，也不强迫用户完成任务。AI 或网络失败不能阻止桌宠窗口、动画、统计和基础互动运行；AI 失败时只取消本次 AI 台词或日报，不使用本地 fallback 台词。

第一阶段是个人本地 MVP，不做账户、云端后端、多设备同步、在线内容市场或商业安装器。

## 2. 已确认的产品和平台决策

### 2.1 平台

- 使用 C#、WPF、Win32 P/Invoke、SQLite 和 `HttpClient`。
- 目标框架固定为 `net10.0-windows`。
- 第一阶段支持 Windows 10 22H2 及以上，优先 x64。
- UI 不使用 Electron、Tauri、WebView、HTML、CSS 或 JavaScript。
- 第一阶段使用单进程 WPF 应用，不创建 Windows Service。
- 应用使用单实例运行。
- 桌宠素材按个人本地资源处理；实现阶段使用 PNG 帧或独立 PNG 帧。

### 2.2 性格

- 默认性格是调皮、欠一点、嘴硬但带有关心。
- 可以吐槽、夸张威胁、自我吹嘘、装作受害者和无厘头联想。
- 不持续打扰用户；主动行为受全局冷却、单活动冷却、安静时段、全屏和暂停控制。

### 2.3 固定默认值

```text
全局活动冷却：20 分钟
每日活动上限：不设置
每日 AI 上限：不设置
安静时段：23:00-08:00，使用本地时区
默认声音：关闭
默认允许受击：开启
受击不产生惩罚
全屏行为：隐藏所有桌宠并暂停新的随机活动
前台使用时间：只要应用处于前台就计时，不设置 idle 超时
锁屏/睡眠/休眠：关闭当前前台会话
本地历史：最多保留 15 个本地日
```

所有活动和时间规则仍可在设置中调整，除非本说明明确要求固定行为。

## 3. 桌宠窗口和互动

### 3.1 窗口行为

桌宠窗口是无边框、透明、可置顶的 WPF 窗口。它支持多显示器工作区定位、拖拽、显示/隐藏、暂停、退出和托盘入口。

拖拽规则：

- 桌宠可以移动到当前显示器边缘；
- 至少保留约 20 个逻辑像素可见；
- 应用重启恢复上次位置；
- 原显示器消失时移动到主显示器；
- 位置超出当前工作区时自动修正；
- 未关闭的气泡跟随桌宠移动。

### 3.2 互动映射

```text
左键单击：普通互动
左键双击：受击
右键单击：特殊互动
右键菜单：不在桌宠窗口中打开，统一通过系统托盘访问
拖拽：移动桌宠
```

双击判定使用 Windows 当前系统双击时间。第一次左键点击会等待系统双击判定窗口；若没有第二次点击，才触发普通互动。

受击有独立冷却，不因连续双击或重复操作造成动画、数据库或 AI 请求爆发。

### 3.3 气泡

每条最终展示的 AI 台词拥有独立气泡：

- 气泡不会自动消失；
- 用户点击右上角关闭按钮后才移除；
- 多个气泡围绕桌宠自动纵向堆叠，避免重叠；
- 空间不足时切换到桌宠另一侧；
- 气泡随桌宠拖拽同步移动；
- 每个气泡使用独立 `RequestId` 和展示状态。

右键 AI 互动先显示占位气泡。占位气泡最多显示 15 秒：

- 15 秒内成功：用 AI 台词替换占位内容；
- 15 秒后成功：只记录，不展示；
- 五次请求全部失败：移除占位气泡，显示非阻塞失败通知；
- 占位内容不写入已展示台词历史，也不参与重复判断。

## 4. 活动和全屏规则

### 4.1 活动调度

活动由本地确定性行为引擎触发，AI 不能决定活动是否发生。行为引擎支持：

- 全局冷却 20 分钟；
- 每活动独立冷却；
- 不设每日活动上限；
- 安静时段；
- 全屏暂停；
- 用户暂停；
- 活动启用/禁用和频率设置；
- 黑名单应用；
- 当前应用类别、窗口标题和使用时段条件。

没有每日上限不代表没有频率控制。单次活动仍受冷却、安静时段、全屏和暂停约束。

### 4.2 全屏

任意一个显示器检测到独占全屏或覆盖整个显示器的无边框全屏窗口时：

```text
隐藏所有显示器上的桌宠
暂停新的随机活动
继续采集前台应用和窗口标题统计
不中断已经发出的 AI 请求
```

普通最大化窗口不算全屏。全屏期间完成的 AI 结果只记录，不展示。

## 5. 使用统计、窗口标题和隐私边界

### 5.1 统计口径

前台应用处于前台期间计入前台使用时间，即使用户正在阅读、看视频或暂时没有输入。应用自身不计入使用总量。

锁屏、睡眠和休眠会关闭当前会话；解锁后重新获取前台窗口并创建新会话。全屏应用仍然计入使用统计。

默认记录：

- 前台应用使用时间；
- 前台应用切换次数；
- 窗口标题变化区间；
- 最长连续前台使用；
- 使用时段和深夜使用；
- 工作/娱乐比例；
- 桌宠互动、受击、随机活动和 AI 请求结果。

### 5.2 窗口标题

窗口标题可以采集并发送给 AI。标题记录规则：

```text
标题变化
  -> 等待稳定 2 秒
  -> 期间再次变化：丢弃前一候选并重新计时
  -> 稳定满 2 秒：记录标题区间
```

在 2 秒内离开窗口的标题不保存。连续相同标题不重复写入。窗口标题最多保存 15 个本地日。

发送给 AI 时不发送完整 15 天原始记录，而是由本地聚合器生成有限上下文：当前应用、当前标题、最近标题变化、使用时间、代表性应用和历史摘要。单次请求有输入字符上限。

### 5.3 不采集内容

默认不采集：

- 键盘具体输入；
- 鼠标轨迹；
- 截图；
- 文档正文；
- 浏览器网页正文；
- 剪贴板内容。

应用名和窗口标题属于用户明确允许发送给 AI 的上下文。API Key 永远不进入 Prompt、普通日志或请求内容。

### 5.4 数据保留

所有本地历史最多保留最近 15 个本地日：

- 使用统计；
- 应用和窗口标题；
- 互动记录；
- AI 候选和请求结果；
- 已展示台词；
- 日报和日报状态；
- 成功、失败和重试记录。

未展示的 AI 结果可以保存为请求记录，但不进入已展示台词的重复判断。

设置和加密 API Key 不属于历史数据，不因滚动清理自动删除。清除历史、恢复默认设置、删除 API Key 是三个独立操作。

## 6. AI 架构

### 6.1 Provider 分工

```text
DeepSeekContentProvider
  -> 生成自然语言候选

JevDecisionProvider
  -> 使用 TypeSafe 官方 API
  -> model = jev-latest
  -> 从合格候选中选择最佳候选

ContentValidator
  -> 本地硬规则

CandidatePoolBuilder
  -> 组织 DeepSeek 候选池

ContentSelector
  -> 调用 Jev 并执行低置信度时的本地平局处理
```

Jev 只负责候选选择，不负责触发行为、执行系统操作、决定是否显示桌宠或修改统计数据。

### 6.2 Key 存储

DeepSeek 和 Jev 使用独立 API Key。两个 Key 都使用 Windows DPAPI 加密，密文存入 SQLite；程序只在实际请求时解密到内存。

API Key 不进入：

- 明文设置对象；
- 普通 SQLite 字段；
- Prompt；
- 日志；
- 异常消息；
- 测试 fixture；
- 源代码。

### 6.3 并发和重试

不同场景的 AI 请求允许并发。每个请求拥有独立的 `RequestId`、场景、超时、重试计数和展示状态。

同一个候选池内部的 DeepSeek 请求串行执行，以减少重复和浪费。Jev 只在当前候选池达到最低数量后执行。

DeepSeek 每次请求返回 6 条候选。候选池没有固定大小上限，至少有 4 条合格候选时进入 Jev 阶段。最多发起 5 次 DeepSeek 请求；五次后仍少于 4 条则失败。

重试退避：

```text
第一次失败后等待 1 秒
第二次失败后等待 2 秒
第三次失败后等待 4 秒
第四次失败后等待 8 秒
```

一次场景最多发起 5 次请求，包含首次请求。每次重试携带已有候选和请求变化编号，明确要求不重复已有候选；本地仍然重新校验。

DeepSeek 单次超时：

```text
问候：8 秒
随机活动：8 秒
用户主动要求台词：10 秒
日报：30 秒
右键特殊互动：8 秒
```

Jev 单次超时固定为 5 秒，也最多发起 5 次请求并使用相同的 `1、2、4、8 秒` 退避。Jev 失败不重新生成 DeepSeek 候选。

所有最终失败都不使用 fallback，只显示非阻塞通知。应用退出时取消所有未完成请求；隐藏、暂停、全屏和切换应用不会取消已发出的请求。

### 6.4 CandidatePool

每个 DeepSeek 响应的候选按以下顺序处理：

```text
解析 JSON
  -> 检查是否为 6 条候选
  -> 本地硬校验
  -> 与当前候选池去重
  -> 与最近 15 天已展示内容比较
  -> 合格候选写入候选池
```

候选池保存所有通过硬校验的候选，不限制单场景候选数量。候选达到 4 条后立即进入 Jev。

Jev 接收：

- 场景类型；
- 当前时间段；
- 当前应用名；
- 当前窗口标题；
- 当前幽默风格；
- 压缩后的近期重复摘要；
- 全部合格候选。

Jev 不接收完整 DeepSeek Prompt、全部 15 天原始窗口标题或被拒绝候选全文。

### 6.5 Jev 选择和低置信度

Jev 只返回：

```text
bestCandidate
confidence
probabilities
```

以下任一条件满足时，由本地规则参与平局处理：

```text
最高概率 < 0.55
或第一名与第二名概率差 < 0.10
```

本地平局规则优先考虑：通过硬校验、近期较少展示、与当前窗口更相关、n-gram 相似度更低、符合幽默风格冷却、文本更短。

如果 Jev 选中的候选不合格，按 Jev 排名寻找下一个合格候选；只有整个请求无有效结果时才重试 Jev。

## 7. 内容规则

### 7.1 普通台词长度

```text
点击 / 受击：8-30 个可见字符
每日问候：10-50 个可见字符
随机活动：10-60 个可见字符
用户主动要求：10-80 个可见字符
```

### 7.2 普通台词硬校验

本地校验包括：

- 非空；
- 长度范围；
- 单段落；
- 不允许 Markdown；
- 禁止客服式开场和 AI 自我介绍；
- 禁止明显的模型套话；
- 禁止连续标点和过量 emoji；
- 不得引入场景未提供的事实；
- 与当前候选池和最近 15 天展示内容不能高度相似；
- 不能连续使用同一幽默风格。

DeepSeek Prompt 会提前要求满足这些规则，但本地 Validator 才是最终准入标准。

### 7.3 右键特殊互动

右键每次都先执行本地动画。以下条件满足任一项且 AI 特殊互动开关开启时，允许调用 AI：

- 当前窗口标题自上次特殊互动后发生变化；
- 最近 15 天没有相似的已展示右键台词；
- 距离上次 AI 右键互动至少 5 分钟；
- 当前处于特殊时间段，例如深夜。

普通左键点击和受击默认使用本地台词，不调用 AI。

## 8. 每日报告

### 8.1 生成时间和门槛

每天按本地时间 18:20 运行一次。统计范围为当天 00:00 到 18:20。

只有截至 18:20 的前台使用时间超过 30 分钟才生成日报。18:20 之后新增的使用时间不会让当天原本跳过的日报重新生成。

如果应用或电脑在 18:20 没有运行，下次启动时检查截至该日 18:20 是否已有超过 30 分钟的统计：

- 有：补生成该日；
- 没有：标记为活动不足，不生成；
- 多天关机时：逐日检查，但没有足够活动的日期直接跳过。

### 8.2 新鲜度规划

本地 `DailyReportPlanner` 为每个报告日期选择：

- 最近 5 天未使用的主题；
- 最近 5 天未使用的报告形式；
- 最近 2-3 天未连续使用的语言风格；
- 当天事实支持的重点。

可用主题包括工作时间、娱乐时间、窗口切换、常用应用、深夜使用、最长连续使用、桌宠互动、工作/娱乐比例和与近期变化。可用形式包括战报、事故调查、颁奖典礼、法庭判决、体育解说、天气预报、侦探记录、绩效评估、新闻快讯和桌宠投诉信。

本地只把压缩后的最近报告摘要发送给 AI，不发送 15 天全部日报原文。

### 8.3 AI 日报流程

```text
DailyReportPlanner
  -> 生成固定报告计划

DeepSeek
  -> 每次生成 6 个版本
  -> 候选池串行补充
  -> 合格版本达到 4 个后停止

Jev / jev-latest
  -> 选择最佳版本

本地
  -> 检查 200-500 个可见字符
  -> 检查空内容、异常格式和高度重复
  -> 展示并保存
```

日报正文允许 AI 自由发挥，不强制逐字保留本地数字或应用名。准确统计在日报窗口的折叠区域中由本地计算并显示。

日报失败时最多重试 DeepSeek 和 Jev 各自的流程；最终失败显示非阻塞通知并提供“重试”按钮。手动重试沿用同一个日报计划、日期和 18:20 截止时间。

日报成功后显示非阻塞通知，用户点击通知打开日报窗口；不自动弹出窗口。隐藏或全屏期间完成的日报只记录，不显示通知。

日报窗口支持查看最近 15 个本地日的报告、跳过原因和失败状态。

## 9. 设置、托盘和启动

设置至少包括：

- 开机启动；
- 桌宠大小、透明度、置顶；
- 活动频率、全局冷却和安静时段；
- 受击开关和声音开关；
- 全屏行为；
- 统计开关；
- AI 总开关和右键 AI 特殊互动开关；
- DeepSeek API Key；
- Jev API Key；
- 清除历史；
- 删除 API Key；
- 恢复默认设置；
- 导出统计；
- 黑名单应用。

开机启动默认关闭。用户开启后使用当前用户注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，启动参数标记为 `--startup`。

开机启动流程：

```text
进程启动
  -> 立即显示托盘图标
  -> 立即初始化后台统计和监听
  -> 等待 10 秒
  -> 显示桌宠并恢复运行
```

用户在等待期间点击托盘“显示”时立即取消等待并显示桌宠。应用单实例运行，第二次启动激活已有实例，不创建第二个进程。

## 10. 性能、生命周期和安全

- 空闲时不使用持续高帧率动画循环；
- 只在动画播放时刷新帧；
- 普通动作目标 12-18 FPS，重点动画目标 24-30 FPS；
- 数据库写入和网络请求不运行在 WPF Dispatcher 线程；
- 所有后台任务使用可取消的 `CancellationToken`；
- 应用退出时先停止 Win32 Hook，再关闭使用会话、刷新批量写入、取消 AI 请求、持久化设置，最后关闭数据库；
- API Key、窗口标题和 Prompt 不写入普通日志；
- 数据库文件位于 `%LOCALAPPDATA%\DesktopPuppy\desktop-puppy.db`；
- 应用自身进程不计入使用统计；
- 只有用户主动执行清除历史时才删除 15 天内数据。

## 11. 第一阶段交付边界

第一阶段包含：

- 桌宠透明窗口和基础动画；
- 单击、双击受击、右键特殊互动和拖拽；
- 多显示器、DPI、置顶、全屏、托盘和单实例；
- 前台应用和窗口标题统计；
- 15 天滚动历史；
- 本地活动调度；
- 每日问候和每日报告；
- DeepSeek 候选生成；
- Jev `jev-latest` 候选选择；
- 内容硬校验、重复检测和失败通知；
- DPAPI 加密 API Key 存储；
- 设置、开机启动、数据清除和导出；
- 自动化测试和手动测试矩阵。

不包含：

- 云端账户；
- 多设备同步；
- 在线内容市场；
- 多 Provider 选择界面；
- Windows Service；
- 复杂成长系统；
- 社交分享；
- 商业安装器优化。

## 12. 验收方向

必须验证：

- 多显示器、DPI 和显示器拔出后的恢复；
- 单实例和开机启动；
- 单击、双击、右键、拖拽和气泡关闭；
- 全屏隐藏和统计继续；
- 锁屏、睡眠、休眠会话关闭；
