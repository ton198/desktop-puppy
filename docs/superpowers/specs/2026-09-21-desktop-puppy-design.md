# Desktop Puppy 需求与设计说明

**日期：** 2026-09-21
**状态：** 需求与架构已讨论，等待实现前审阅
**项目性质：** 个人使用、非商业桌面宠物应用

## 1. 产品定位

Desktop Puppy 是一个运行在 Windows 桌面的调皮型常驻桌宠。它通过轻量动画、受击互动、随机活动、每日问候和幽默的电脑使用总结，为用户提供有个性的桌面陪伴。

产品不以生产力工具为主，也不强迫用户完成任务。网络或 AI 失败不能影响桌宠的基础互动。

## 2. 已确认决策

### 2.1 产品性格：B 调皮捣蛋型

- 会主动发起低频互动；
- 会吐槽用户的电脑使用行为；
- 可以有轻微捣蛋、夸张威胁和自我吹嘘；
- 嘴上嫌弃但实际带有关心；
- 不能持续打扰，必须受冷却时间、安静时段和全屏规则控制。

### 2.2 AI 使用策略：B 混合模式

- 普通点击、受击和高频反馈优先使用本地人工台词库；
- 每日问候、重要随机活动和每日统计总结允许调用大模型；
- AI 只负责在已确定的场景中生成或改写台词，不负责决定何时出现或执行什么行为；
- 没有 API Key、网络失败、超时、响应格式错误或内容校验失败时，立即使用本地 fallback；
- 设置中可以关闭 AI，并限制每日请求次数。

### 2.3 AI Provider

第一阶段只接入 DeepSeek，默认模型为 deepseek-flash。用户在设置页填写自己的 API Key。Provider 必须通过独立适配器封装，不能把 DeepSeek 请求细节散落在行为模块中。

API Key 必须使用 Windows 本地安全存储能力保存，不得明文写入普通配置文件、SQLite 普通字段、日志或源代码。

### 2.4 技术栈

- C#；
- 当前 .NET LTS；
- WPF；
- Win32 API / PInvoke；
- SQLite；
- PNG 精灵帧或独立 PNG 帧；
- HttpClient 调用 DeepSeek；
- 不使用 Electron、Tauri、WebView、HTML、CSS 或 JavaScript 作为 UI 技术。

### 2.5 本地优先

使用统计、互动历史、台词历史和应用设置默认保存在本机。项目不包含自有云端后端，不做账户、多设备同步或在线内容市场。

## 3. 功能需求

### 3.1 桌宠窗口

- 无边框透明窗口；
- 桌面常驻；
- 可配置置顶；
- 拖拽移动；
- 单击、双击、右键、悬停交互；
- 多显示器工作区定位；
- 隐藏、暂停、退出；
- 系统托盘入口；
- 全屏应用检测；
- 全屏时按设置隐藏桌宠并暂停非必要活动。

### 3.2 动画和受击

基础状态包括待机、发呆、走动/跳跃、开心、生气、睡觉、受击、被点击和随机活动动作。

受击必须：

- 立即播放视觉反馈；
- 可选播放声音；
- 记录时间和次数；
- 触发本地或受控台词；
- 有点击/受击冷却，不能造成请求爆发；
- 可在设置中关闭受击或声音。

### 3.3 每日问候

- 每天首次启动问候；
- 按早上、午间、下午、晚上、深夜区分；
- 可参考星期、日期和近期互动；
- 短时间内不重复；
- 本地和 AI 内容混合；
- 记录展示历史，失败时使用 fallback。

### 3.4 随机活动

初始活动包括突然吐槽、短动作、长时间工作反应、频繁切换窗口反应、夜间反应、长时间空闲反应、特定应用类别反应、被点击/拖拽/受击反应。

活动支持全局冷却、独立冷却、每日上限、安静时段、全屏暂停、启用/禁用和频率调整。活动由本地行为引擎决定，模型不能直接调度活动。

### 3.5 使用统计

默认记录：电脑活跃时长、空闲时长、前台应用使用时长、最长使用应用、应用切换次数、最长连续使用时长、使用时间段、深夜使用、工作/娱乐比例、桌宠互动次数、受击次数、活动次数、AI 成功/失败/fallback 次数。

默认不记录：键盘具体输入、鼠标轨迹、截图、文档内容、浏览器网页正文、剪贴板内容。默认按进程名归类，不记录窗口标题；窗口标题只有用户主动开启时才考虑，并且发送给 DeepSeek 前还要单独提示。

### 3.6 每日总结

每天生成幽默总结，可包含总活跃时间、最长连续使用、最常用应用、窗口切换次数、工作/娱乐比例、深夜使用、桌宠互动、与昨天变化、吐槽和一句轻量建议。

数字和事实必须由本地模块计算。模型只能润色，不能修改数字、应用名或增加不存在的事实。校验失败时使用本地模板报告。

### 3.7 设置和隐私

至少包括：开机启动、桌宠大小、透明度、置顶、活动频率、安静时段、受击开关、声音开关、全屏行为、统计开关、AI 开关、AI 模式、DeepSeek API Key 管理、每日请求上限、清除历史、导出统计、黑名单应用。

## 4. 防止 AI 味的内容设计

### 4.1 核心原则

本地行为引擎决定“做什么”，大模型只决定“怎么说”。AI 是内容增强器，不是行为控制器。

### 4.2 人设规则

台词需要调皮、欠一点但不恶意、嘴硬关心、具体描述场景、句子短、可以夸张或无厘头、偶尔自我吹嘘、不要解释笑点、不要每句都写成鼓励或建议。

强烈过滤：作为一个 AI、希望这对你有所帮助、让我们一起、请注意劳逸结合、客服式开场、长篇解释、机械复述输入、模型自我介绍和未经提供的事实。

### 4.3 内容管线

~~~text
本地事件引擎
 -> 场景卡：事件、时间、应用类别、用户状态、语气、幽默方式、允许事实、长度
 -> 人设配置和人工 few-shot 台词
 -> DeepSeek 生成 3-5 个候选
 -> 本地校验：长度、格式、禁用短语、事实、重复、句式相似度
 -> 选择一条并缓存
 -> 播放动画和展示台词
~~~

候选应尝试轮换嘴硬关心、夸张威胁、冷淡吐槽、自我吹嘘、假装专业、无厘头联想、装作受害者等幽默方式。

本地检查包括空值、长度、Markdown、多段落、禁用词、表情符号过量、连续标点、重复文本、近似句式和同一幽默方式连续使用。第一版不需要向量数据库，标准化文本加 n-gram 相似度即可。

人工种子台词既用于离线 fallback，也用于 few-shot 和改写模式。建议第一批为问候、受击、长时间工作、深夜、点击、发呆和每日总结各准备约 20 条。

### 4.4 每日总结安全边界

本地先生成不可变的 DailyReportFacts，再让模型生成标题、评价、吐槽和建议。模型只能使用 facts 中的数字和名称；程序需要检查数字和名称是否被修改。

### 4.5 AI 请求策略

- 受击和普通点击：默认不调用 AI；
- 普通随机活动：优先本地，低频调用 AI；
- 每日问候：允许 AI；
- 重要活动：允许 AI；
- 每日总结：允许 AI；
- 用户主动要求“再说一句”：允许 AI；
- 所有请求异步执行，不阻塞 UI；
- 超时、错误、限额或校验失败立即 fallback；
- 支持每日调用上限和完全离线模式。

## 5. 性能要求

- 空闲时不持续高帧率刷新；
- 仅在动画播放期间刷新；
- 普通动作目标 12-18 FPS；短时重点动画目标 24-30 FPS；
- 动画结束停止计时器；
- 避免大面积模糊、重型阴影和大图重复解码；
- 统计优先使用系统事件监听，低频检查作兜底；
- SQLite 批量写入；
- 网络请求和数据库写入不运行在 WPF UI 线程；
- 全屏或用户暂停时关闭非必要工作。

## 6. 架构边界

~~~text
DesktopPuppy.App
  PetWindow / AnimationEngine / InteractionEngine
  ActivityEngine / GreetingService / DailyReportService
  UsageCollector / DailyUsageAggregator
  ContentService / ContentValidator / ContentCache
  DeepSeekContentProvider / SecureApiKeyStore
  SQLite Storage / SettingsService
  NativeWindows: PInvoke、托盘、全屏、前台窗口、开机启动
~~~

第一阶段使用单进程 WPF 应用，不创建 Windows Service。所有 UI 更新回到 WPF Dispatcher，所有后台任务可取消。

## 7. 第一阶段边界

第一阶段交付一个可长期运行的个人 MVP：桌宠窗口、基础动画、受击、低频活动、每日问候、本地统计、每日总结、DeepSeek API Key、混合 AI、AI 内容校验、fallback、设置、托盘、数据清除和自动化测试。

不纳入第一阶段：云端账户、多设备同步、在线内容市场、多 Provider、复杂成长系统、社交分享、自动下载第三方资源、商业安装器优化。

## 8. 默认值候选

实现前建议最终确认：活动全局冷却 20 分钟、每日活动上限 8 次、安静时段 23:00-08:00、每日 AI 上限 20 次、默认不播放声音、默认允许受击但不产生惩罚、全屏时隐藏并暂停随机活动。所有数值都应可配置。

## 9. 验收方向

需要验证多显示器/DPI、长时间运行、受击和活动不卡顿、AI 失败 fallback、短期不重复、API Key 不泄露、全屏规则、清除历史、空闲时 CPU 下降，以及每日统计事实不被模型篡改。
